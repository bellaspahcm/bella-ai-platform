## Observed behavior and counterexamples

1. `daily-care.service.ts:238–243,304–325` consumes the actual Attendance contract but returns seven Care fields without `attendance` or `attendanceNote`. The new service test exercises both real implementations with a synthetic caller and confirms this loss. Returning Attendance DTO directly would also omit the existing `care` composition and expose a different shape.
2. `request-context.ts:110–125` rechecks each enrollment after the roster read, retaining only the same tenant/course/Party, active status and enrollment date. A substitute must preserve this filter; an Attendance roster alone is not the final Care-authorized roster.
3. `care/bulk/route.ts:126–149` performs a later projection read filtered by tenant/day/joined course, then uses last-row-wins **Party** mapping. `attendance.contract.impl.ts:206–230` filters state by the roster's **enrollment IDs**, validates uniqueness/scope and maps by enrollment. A synthetic caller-visible second enrollment for the same Party produces `absent` in the route versus `present` in the contract. This is a conditional source counterexample, not a finding that current DB constraints/RLS expose those rows.
4. A controlled state change between the earlier contract read and M005 yields earlier `present` versus current response `absent`. Reusing the earlier DTO changes which observation is returned. This test proves source timing semantics under supplied dependency results, not PostgreSQL isolation or a live race incident.
5. Earlier contract failure inside roster authorization maps to `CARE_ENROLLMENT_SCOPE_UNAVAILABLE`; a later M005 projection failure maps to `CARE_DATA_UNAVAILABLE` (both 503). Both paths are executed by the new tests using the actual contract. Moving/remapping a read cannot assume error equivalence. The status validation difference alone is not an unconditional counterexample: on an unchanged snapshot the earlier contract already rejects an invalid status before M005 is reached.
6. Current normal statuses `present/absent/excused`, object/array joined relation shapes, `rollCallTime: null` and `attendanceNote: null` are characterized. A future adapter must keep the current external payload rather than forward additional Attendance DTO fields.

**Result: M005 HELD / BLOCK.** Neither reusing the discarded first DTO nor calling the contract again is proved equivalent. A second contract invocation would rerun roster identity resolution/validation instead of the current joined read. No contract or runtime edit was made, and no new exception is proposed. The minimum owner/contract issue is the authoritative observation (first or later read), enrollment-versus-Party resolution and retained error mapping, followed by proof on a suitable permitted environment; these are not answered by seven existing control approvals.
