# E2E transaction timeout enforcement

`connection-settings-diagnostic.json` reads actual settings through the exact approved project's configured TLS-verified connection. Despite the pg client's startup options, Supavisor returned `statement_timeout=2min`, `lock_timeout=0`, `application_name=Supavisor`. Startup configuration is therefore not evidence that the required bounds are effective. A preceding execution failed `QUERY_READ_TIMEOUT` during preparation, before any Auth/business fixture was created; both approved packages were restored to the original fingerprint. Its raw report and native exit1 remain unchanged.

The harness now starts each explicit transaction with `SET LOCAL lock_timeout='5s'` and `SET LOCAL statement_timeout='30s'` and verifies both values. A statement outside an explicit transaction receives its own bounded transaction. These are connection-local execution controls; no role, helper, policy, schema/default ACL or business semantic is changed. Existing savepoint handling remains intact. Every failure records only its fixed phase, error code, elapsed time and parameterized statement hash.

A failed acknowledgement cannot establish transaction state. Ordinary statements are blocked until an acknowledged full ROLLBACK resynchronizes the connection. A possible COMMIT remains a sticky unproven outcome even after ROLLBACK, prohibits retention and forces the run to FAIL. Catalog and fixture readback still determine actual recovery; a ROLLBACK acknowledgement does not prove an earlier commit was undone.

Three independent read-only reviewers examined blind, edge and acceptance perspectives. Their stale-transaction, uncertain-commit and phase-receipt findings were fixed; bounded rereview returned no outstanding findings. No reviewer ran remote commands or granted change authority. Five local fault tests passed, zero failed/skipped, native exit0: coordinated retention failure recovery; interrupted checkpoint publication; Supavisor startup timeout loss; lost COMMIT/ROLLBACK acknowledgements; replacement Party rejection. `local-verification.json` and `local-fault-tests.log` preserve executed local evidence. Real DB acceptance remains a separate timestamped result.
