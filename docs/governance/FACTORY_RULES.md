# Bella Factory Operating Rules

**Scope:** Existing Bella Factory work across all current and future Products and platform tasks when Factory is selected and the task is admitted.

Apply [Autonomous Execution](OPERATIONAL_RULES.md) and the Constitution's [Factory Intake](BELLA_AI_CODING_CONSTITUTION.md#factory-intake-from-project-codex-chat). The Constitution owns routing, authority, evidence requirements, and held-run semantics; the launcher's actual admission, role, command, retry, and budget limits remain binding. This document adds no dispatcher, gate, or approval stage.

- **Lead carries the authorized task forward.** Establish scope, acceptance criteria, owned files, source revision, permissions, and verification using existing task records. Carry valid user decisions through handoffs; do not request the same approval for each role or ask an early role to prove evidence that a later role must produce.
- **Builder resolves implementation obstacles within its assignment.** Diagnose root causes, use permitted alternatives, and repair related code/configuration/fixture issues where authorized. Respect protected files, existing contracts, test requirements, and execution limits.
- **Verify and Reviewer preserve independent judgment.** Verify runs the assigned checks and reports actual results. Reviewer evaluates the actual candidate and evidence. Neither silently repairs implementation, weakens checks, invents missing receipts, or substitutes a user's approval for verification. Return actionable findings to the owning role through the existing supported revision path.
- **Routine handoffs proceed without another human approval.** Lead → Builder → Verify → Reviewer transitions and revisions already allowed by the selected launcher use the task's valid authority. A role transition alone is not a new business decision or request for access. Do not activate additional agents or multi-agent execution beyond the selected workflow's authority.
- **Respect terminal results while continuing independent work.** The operational rule does not authorize extra commands, retries, revisions, broader admission, or new tasks around a restriction. Preserve a terminal `HELD` and its candidate/evidence; do not resume, automatically retry, replace that run, edit its candidate, or relabel direct work as Factory evidence. Continue only independent authorized work permitted by the Constitution. Escalate the specific unresolved dependency when human action is actually required.
- **Close with evidence at the declared scope.** Retain role handoffs, verification and independent read-back required by the selected workflow, and report unfinished criteria honestly. Commit, push, PR, merge, deployment, and Go-Live retain their separate authorization; Factory completion does not grant it.

These instructions define expected behavior. They do not claim that every native role currently loads this file or that a live run has demonstrated fewer interruptions. Evaluate those claims with actual task evidence under the Constitution's [Enforcement Evidence](BELLA_AI_CODING_CONSTITUTION.md#enforcement-evidence), without changing runtime controls or copying these rules into Product checklists.
